Core Data Structures

Arrays · Linked Lists · Stacks · Queues

Core Principle: A data structure is a systematic way to organise, store, and retrieve data so that operations on it are efficient. Every structure involves a trade-off between space and time.

1. Arrays

Array in memory — contiguous allocation
Strengths
  • O(1) random access by index
  • Cache-friendly (contiguous memory)
  • Simple binary search in sorted arrays
Weaknesses
  • Fixed size (static arrays)
  • O(n) insertion/deletion (shifting)
  • Wasted space if not full
HPCL Exam Tip: 2D arrays are stored in row-major order in C/C++, column-major in Fortran. Address of A[i][j] = Base + (i×cols + j) × size.

2. Linked Lists

Singly Linked List — nodes connected by pointers
Types of Linked Lists
  • Singly: one pointer (next)
  • Doubly: prev + next pointers
  • Circular: tail → head
  • Skip List: multi-level pointers
Key Operations
  • Insert head/tail: O(1)
  • Search: O(n)
  • Delete (known node): O(1)
  • Access by index: O(n)

3. Stacks

A LIFO (Last-In First-Out) structure. Think of a pile of plates — you add to and remove from the top only.

Stack operations — push and pop

4. Queues

A FIFO (First-In First-Out) structure. Elements are added at the rear and removed from the front.

Queue — enqueue at rear, dequeue from front
Queue Variants
  • Circular Queue: wraps around; no wasted space
  • Deque (Double-ended): insert/delete both ends
  • Priority Queue: highest priority served first
Applications
  • OS process scheduling
  • Printer spooling
  • BFS graph traversal
  • Network packet buffering
Exam Focus: Know that a priority queue can be efficiently implemented using a min-heap (O(log n) insert/extract). This is used in Dijkstra's and Prim's algorithms.

Trees & Heaps

Binary Trees · BST · AVL · Heaps

Tree: A hierarchical data structure with a root node, where each node has zero or more children. No cycles. A tree with n nodes has exactly n−1 edges.

Binary Search Tree (BST)

BST — left child < parent < right child
BST Operations
  • Search: O(log n) avg, O(n) worst
  • Insert: O(log n) avg
  • Delete: O(log n) avg
  • Inorder traversal → sorted output
Tree Traversals
  • Inorder (L → Root → R): sorted
  • Preorder (Root → L → R): copy tree
  • Postorder (L → R → Root): delete tree
  • Level-order (BFS): level by level

AVL Trees (Self-Balancing BST)

An AVL tree maintains the balance factor = |height(left) − height(right)| ≤ 1 at every node. This ensures O(log n) operations always.

AVL Rotations — restoring balance after insert

Heaps

A complete binary tree satisfying the heap property. Stored efficiently as an array — no pointers needed.

Max-Heap — parent ≥ children. Stored in array: parent at i, children at 2i+1 and 2i+2
Heap Operations
  • Insert (+ heapify up): O(log n)
  • Extract min/max: O(log n)
  • Peek min/max: O(1)
  • Build heap from array: O(n)
Applications
  • Heap Sort: O(n log n), in-place
  • Priority Queue: Dijkstra's, Prim's
  • Median finder: two-heap trick
  • K largest/smallest elements
Exam Tip: Heap sort is not stable. Its best/worst/avg time is all O(n log n). Build heap takes O(n) — not O(n log n). This is a common trick question.

Graphs, Traversals & Shortest Paths

BFS · DFS · Dijkstra · Bellman-Ford · MST

Graph G = (V, E) — V vertices and E edges. Can be directed/undirected, weighted/unweighted, cyclic/acyclic.

Graph Representations

Adjacency Matrix

2D array, A[i][j] = weight if edge exists, 0 otherwise.

Space: O(V²) · Edge lookup: O(1)

Best when: dense graphs (many edges)

Adjacency List

Array of lists. Each vertex stores its neighbours.

Space: O(V+E) · Edge lookup: O(degree)

Best when: sparse graphs (few edges)

Graph Traversals

BFS vs DFS — from node A on the same graph
BFS — Breadth First
  • Uses a Queue
  • Explores neighbours level by level
  • Finds shortest path in unweighted graphs
  • Time: O(V+E) · Space: O(V)
DFS — Depth First
  • Uses a Stack (or recursion)
  • Goes deep before backtracking
  • Detects cycles, topological sort
  • Time: O(V+E) · Space: O(V)

Minimum Spanning Tree (MST)

MST: A spanning tree of a weighted, connected, undirected graph with the minimum total edge weight. A tree with V vertices has exactly V−1 edges.
Prim's vs Kruskal's — both produce the same MST, different strategies

Shortest Path Algorithms

Dijkstra's Algorithm
  • Single-source shortest path
  • Works on non-negative weights only
  • Uses a min-heap (priority queue)
  • Time: O((V+E) log V)
  • Greedy — always picks closest unvisited node
Bellman-Ford
  • Single-source; handles negative weights
  • Detects negative weight cycles
  • Time: O(V·E) — slower
  • Relaxes all edges V−1 times
  • Used in routing protocols (RIP)
Floyd-Warshall
  • All-pairs shortest path
  • Dynamic programming approach
  • Time: O(V³)
  • dp[i][j] = min distance i→j
  • Simple 3-nested-loop implementation
Key Distinctions for exam:
· Dijkstra: non-negative weights, greedy, O((V+E) log V)
· Bellman-Ford: negative weights OK, DP-style, O(VE)
· Floyd-Warshall: ALL pairs, O(V³), simple but costly

Hashing

Hash Tables · Collision Resolution · Applications

Hashing maps a key to an index in a fixed-size array using a hash function. Goal: achieve O(1) average-case for insert, delete, and search.
Hash Table — key → hash function → bucket index

Collision Resolution Techniques

Chaining (Open Hashing)

Each bucket holds a linked list. Collisions stored in same bucket's list.

  • Simple to implement
  • Load factor α = n/m (can exceed 1)
  • Search: O(1+α) average
  • Never full; easy deletion
Open Addressing (Closed Hashing)

All elements stored in the table itself. Probe sequence to find empty slot.

  • Linear probing: h(k)+1, +2, +3…
  • Quadratic probing: h(k)+1², +2²…
  • Double hashing: h1(k)+i·h2(k)
  • Load factor must stay below 1
Load Factor (α): If α is too high, collisions increase and performance degrades to O(n). A good hash table keeps α < 0.7 and resizes (rehashing) when needed — typically doubling the table size.
Common Hash Functions:
· Division method: h(k) = k mod m (m should be prime)
· Multiplication method: h(k) = ⌊m·(k·A mod 1)⌋, A ≈ 0.618
· Universal hashing: random selection from family of functions

Algorithm Design Techniques

Greedy · Dynamic Programming · Divide & Conquer

Three paradigms — when to use which

1. Greedy Algorithm

Makes the locally optimal choice at each step, hoping it leads to a globally optimal solution. Works when the problem has greedy choice property and optimal substructure.

Classic Greedy Problems
  • Activity Selection: pick max non-overlapping intervals
  • Fractional Knapsack: sort by value/weight ratio
  • Huffman Coding: min-frequency chars get longer codes
  • Prim's/Kruskal's MST
  • Dijkstra's shortest path
When Greedy Fails

0/1 Knapsack — can't take fractions, so local best ≠ global best.

Greedy gives wrong answer; need DP instead.

Always verify with a counterexample before applying greedy.

2. Dynamic Programming (DP)

Solves problems by combining solutions of overlapping subproblems. Two approaches:

Top-down (Memoization) vs Bottom-up (Tabulation) — Fibonacci example
DP Prerequisites
  • Optimal substructure: optimal solution built from optimal sub-solutions
  • Overlapping subproblems: same subproblems computed multiple times
  • Both must hold → DP is applicable
Classic DP Problems
  • 0/1 Knapsack: O(nW)
  • Longest Common Subsequence (LCS)
  • Matrix Chain Multiplication
  • Edit Distance (Levenshtein)
  • Floyd-Warshall (all-pairs SP)

3. Divide and Conquer

Splits the problem into independent subproblems (unlike DP's overlapping subproblems), solves each recursively, and combines results.

Master Theorem — solving T(n) = aT(n/b) + f(n)
Master Theorem Examples:
· Merge Sort: T(n) = 2T(n/2) + O(n) → Case 2 → O(n log n)
· Binary Search: T(n) = T(n/2) + O(1) → Case 2 → O(log n)
· Strassen Matrix Mult: T(n) = 7T(n/2) + O(n²) → Case 1 → O(n^2.81)
DP vs Greedy — the key exam question:
Both need optimal substructure. But DP also needs overlapping subproblems and explores all options. Greedy makes one irrevocable choice. 0/1 Knapsack → DP. Fractional Knapsack → Greedy.
